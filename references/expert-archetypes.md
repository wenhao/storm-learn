# 动态专家角色池（技能类 / 行业类）

使用方式：先判断主题类型 → 从对应池中挑 4-5 个 → **按主题改写角色名与立足点**（禁止原样照抄）→ 补充该主题特有的隐藏坑点。

---

## 一、技能类主题专家池

适用于：编程、数据分析、写作、设计、剪辑、销售话术、外语、乐器、健身、摄影、烹饪等"能练出肌肉记忆"的主题。

| 角色原型 | 立足点 | 典型核心认知 | 典型隐藏坑点（需按主题改写） |
|---|---|---|---|
| **学院派教练**（科班/体系派） | 强调正确的基本功与体系 | "没有体系的速度是瞎跑，前三个月慢就是快" | 教材里的标准解法在真实项目里往往要打折；练基本功时**练错版本比不练更糟**（动作定型后难改） |
| **野路子老手**（自学/实战派） | 强调能出活、能交付 | "先做出一坨能跑的东西，再谈优雅" | 老手的"直觉"来自上千次试错，抄他的捷径会跳过他踩过的坑；他的环境/版本/资源与你不同 |
| **阅卷裁判**（评分/标准派） | 知道评分标准与扣分点 | "考场上没人看你过程多努力，只看交付物" | 评分标准里藏着**隐性权重**（如代码可读性、边界处理），公开的标准往往不是真实标准 |
| **返工修复师**（排错/救火派） | 见过的失败比成功多 | "80% 的时间花在排查，不是创造" | 报错信息指向的位置常常不是真正出错的位置；日志记录时机不对等于没记 |
| **刻意练习设计师** | 设计反馈回路与难度曲线 | "没有即时反馈的练习只是重复，不是进步" | 难度设在舒适区毫无效果、设在恐慌区会放弃；**85% 成功率**区间最有效；重复练已会的题是自我感动 |
| **认知负荷管家** | 关注工作记忆与组块化 | "一次塞 7 个新概念，等于一个都没学会" | 新手同时学工具 + 学概念 + 学领域知识会三重超载；先自动化底层动作再上难度 |
| **防割韭菜顾问** | 辨别真假高手与无效课程 | "看他的产出和失败案例，不看他的头衔和粉丝数" | 教程里的 demo 都是"挑过的顺境"，真实数据脏 10 倍；免费内容常故意留坑引导付费 |

**技能类推荐组合**（4-5 个）：

- 通用默认：学院派教练 + 野路子老手 + 阅卷裁判 + 刻意练习设计师 + 防割韭菜顾问
- 强实操（编程/剪辑/设计）：野路子老手 + 返工修复师 + 阅卷裁判 + 认知负荷管家
- 强表达（写作/销售/演讲）：阅卷裁判 + 刻意练习设计师 + 野路子老手 + 防割韭菜顾问

## 二、行业类主题专家池

适用于：新能源、SaaS、跨境电商、半导体、医疗、教育、AI 应用、餐饮连锁等"看懂格局与钱流"的主题。

| 角色原型 | 立足点 | 典型核心认知 | 典型隐藏坑点（需按主题改写） |
|---|---|---|---|
| **一线从业者**（产线/门店/项目现场） | 讲的是每天真实发生什么 | "PPT 上的流程和车间里的流程是两回事" | 行业报告的"平均数据"掩盖了**头尾差异**；一线知道哪些指标是糊弄检查的 |
| **投研分析师** | 看钱怎么赚、谁在赚钱、估值逻辑 | "看不懂单位经济模型，就别谈行业前景" | 公开财报的口径可调（收入确认方式、关联交易）；热点赛道的新闻有 6-12 个月滞后 |
| **供应链/渠道老炮** | 看上下游、成本结构与议价权 | "利润不在品牌方手里，在卡脖子的那一段" | 关键环节的**产能瓶颈与账期**决定生死，这些不在新闻里；号称的产能和真实产能常有 30% 差距 |
| **监管/合规视角** | 看政策红线与牌照 | "一个文件能让整个赛道归零，也能让它起飞" | 政策有**征求意见稿到正式稿**的时间差窗口；地方执行口径与中央文件不一致 |
| **客户/用户代表** | 看真实需求与付费意愿 | "用户说想要的，不等于他肯掏钱的" | 需求方与付费方分离（B 端尤其明显）；行业内的"标杆客户"常常是补贴出来的 |
| **技术路线图观察者** | 看技术成熟度与替代风险 | "今天的主流派，可能是明天的包袱" | 技术 S 曲线的**死亡之谷**；押注路线的沉没成本会让整个行业嘴硬 |
| **周期与历史对照者** | 用其他行业/其他地区的历史做对照 | "这个行业正在重演 X 行业 5 年前的故事" | 简单类比会忽略制度与市场结构差异；"这次不一样"通常是最贵的四个字 |
| **防割韭菜顾问** | 辨别包装过的行业叙事 | "凡是把'万亿赛道'挂嘴边的，先问他在哪一层收钱" | 行业培训/加盟/社群的主要收入往往来自卖课而非主业 |

**行业类推荐组合**（4-5 个）：

- 通用默认：一线从业者 + 投研分析师 + 供应链老炮 + 监管合规 + 防割韭菜顾问
- 强监管（医疗/教育/金融）：监管合规 + 一线从业者 + 投研分析师 + 周期对照者
- 强技术（半导体/AI/新能源）：技术路线图观察者 + 供应链老炮 + 投研分析师 + 周期与历史对照者
- 强消费（餐饮/零售/内容）：客户/用户代表 + 一线从业者 + 供应链老炮 + 防割韭菜顾问

## 三、隐藏坑点写作公式

每条坑点必须同时命中三要素，缺一判 Fail：

```
具体场景（在 X 情况下）+ 具体后果（会导致 Y，代价是 Z）+ 规避动作（所以要做 W）
```

**合格示例**：
> 看到教程里的 `pip install xxx` 直接复制（场景），会装上与你项目不兼容的最新版依赖，报错信息却指向你的代码而非依赖（后果），所以先建虚拟环境并锁定版本号再装（规避动作）。

**不合格示例**：
> 要注意版本问题，建议多实践。（无场景、无后果、无动作）

## 四、辨伪标准写作公式

```
看他做什么（可观察行为） + 不看他说什么（被包装的信号） + 一个反问验证法
```

**合格示例**：
> 判断一个老师是否真懂：让他现场改一段你写崩了的代码，看他是上来就重写还是先问你"当时的输入是什么"（可观察行为）；不看粉丝数和课程销量（包装信号）；反问一句"这个方案在什么情况下会失效"，答不上来的基本是背稿。

## 五、专家视角冲突设计表

避免 5 个视角同质化，至少保证一组直接冲突：

| 冲突组 | A 方主张 | B 方主张 | 对初学者的价值 |
|---|---|---|---|
| 体系 vs 速成 | 先打基础再动手 | 先做出东西再补基础 | 明确自己处于哪个阶段该听谁的 |
| 深度 vs 广度 | 一个点挖到底 | 先摸清全景 | 防止在错误方向上深挖 |
| 理想方案 vs 交付方案 | 应该用最优解 | 先交付再优化 | 理解工程约束 |
| 追随主流 vs 押注边缘 | 学主流最稳妥 | 主流很快会饱和 | 建立自己的判断而非盲从 |
| 单干 vs 借力 | 能力要长在自己身上 | 会用工具/外包就够了 | 明确投入产出比 |
