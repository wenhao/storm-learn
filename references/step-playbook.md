# 11 步逐步执行细则（Step Playbook）

每一步包含：**目标** / **输出骨架** / **硬性约束** / **反例（不合格特征）** / **收尾语**。
执行某一步前只读该步章节即可。

**类型判定前置规则**（Step 1 之前完成）：

| 类型 | 判定依据 | 代表作息 |
|---|---|---|
| 技能 | 有明确的动作序列、可反复练、有快慢对错之分 | 每日练 + 即时反馈 |
| 行业 | 目的是看懂格局、术语、钱怎么流动、谁赚谁亏 | 每天读一手材料 + 输出一页判断 |
| 混合 | 既要懂行业又要动手（如"AI 产品运营"） | 前 5 步按行业，6-8 步按技能 |

## Step 1：动态专家视角拆解

**目标**：用 4-5 个互相冲突或互补的专家视角，把主题拆成多维认知地图，并暴露外行看不见的隐藏坑点。

**输出骨架**：

```markdown
### 专家视角矩阵（<主题>）

| # | 专家角色 | 立足点 | 核心认知（一句狠话） | 隐藏坑点（外行不知道的潜规则） | 辨伪标准 |
|---|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |
| 4 | | | | | |
| 5 | | | | | |

**视角冲突提示**：（说明哪两个视角会打架，以及为什么这种冲突对初学者是好事）
**如果只听一个人的话**：（警告：只听 X 会付出什么代价）
```

**硬性约束**：

- 角色从 `expert-archetypes.md` 中挑选并**按主题改写**，禁止原样照抄通用角色名
- 每个"隐藏坑点"必须包含**具体场景 + 具体后果 + 可操作的规避动作**三要素
- 至少 1 个视角是"反主流 / 唱反调"的
- "辨伪标准"要给可观察信号（看他做什么、不看他说什么）

**反例（判 Fail）**：

- 坑点写成"要打好基础""需要多思考""保持热情"
- 5 个视角说的其实是同一件事
- 角色与主题不匹配（给"学吉他"配"分布式系统专家"）

## Step 2：矛盾与盲区清单

**目标**：把领域内的公开争议和初学者的真实认知盲区摆到台面上，避免"只学了一种说法还以为掌握了"。

**输出骨架**：

```markdown
### A. 争议与矛盾清单

| # | 争议点 | 主流说法 | 反方说法 | 证据强弱（强/中/弱 + 依据） | 适用边界（什么情况下谁对） | 我的建议 |
|---|---|---|---|---|---|---|

### B. 初学者 5 大盲区

| # | 盲区 | 典型表现（你会这样） | 后果 | 自检方法（30 秒自查） | 破解动作 |
|---|---|---|---|---|---|
```

**硬性约束**：

- 争议必须真实存在，不是人为制造的"有人说 A 有人说 B"
- 证据强弱要标注来源类型（同行评议论文 / 官方文档 / 大厂实践 / 个人博客 / 坊间传言）
- 盲区必须切中**初学者真实痛点**（如"以为跑通 demo 就是会用"），不能写"不够努力"
- 每条盲区配一个**可自测的问题**

## Step 3：精炼行动简报

**目标**：把前两步压缩成能在 60 秒内讲完、今天就能动手的东西。

**输出骨架**：

```markdown
### 60 秒讲稿（XXX 字，可朗读计时）
<200-300 字，口语化，无术语或术语立刻白话解释>

### 5 条铁律
1. <祈使句，带否定边界>
2. ...

### 今日最小可行切入点（≤30 分钟）
- 准备：<需要什么，1 分钟>
- 动作 1：<具体到命令/点击/写出什么>
- 动作 2：
- 完成标志：<可眼睛看见的结果>
```

**硬性约束**：

- 讲稿字数 200-300，写完后默读计时，超 60 秒必须删
- 铁律用祈使句，每条含"不要做什么"
- 切入点必须在 30 分钟内产出**可见结果**（一个文件 / 一次成功的运行 / 一段写出来的话）

## Step 4：可信度评分与验证规划

**目标**：对前面给出的关键论断做自我怀疑式打分，并给出一手查验路径，培养学习者的独立验证能力。

**输出骨架**：

```markdown
### 关键论断靠谱度评分

| # | 关键论断 | 靠谱度（1-5） | 打分理由 | 一手验证路径（具体到文档/论文/数据库/仓库/年报） | 验证成本 |
|---|---|---|---|---|---|

### 评分口径
5 = 官方文档/标准/一手数据直接支持；4 = 行业公认 + 有公开案例；3 = 主流经验但缺硬证据；2 = 有争议；1 = 传闻/营销话术

### 今日 3 条验证任务
1. <打开 X 的 Y 章节，核对 Z 这句话，预期看到什么>  （≤10 分钟）
2. ...
3. ...
```

**硬性约束**：

- 至少覆盖 Step 1-3 中的 5 条关键论断
- 凡 ≤3 分必须给出**可点击 / 可检索的具体路径**（"RFC 7231 第 6.5.1 节""国家统计局分行业年度数据""某仓库 README 的 Benchmark 表"），禁止写"可以上网查"
- 验证任务必须是今天能做完的，且写明"看到什么算验证成功 / 看到什么算证伪"

## Step 5：精选资料与一周路线

**目标**：只给 3-5 个真正值得读的材料，配 2:8 的实操路线。

**输出骨架**：

```markdown
### 精选资料（3-5 个）

| # | 资料 | 类型 | 权威度 | 为什么是它 | 精读范围（读哪章/哪节/哪几个案例） | 预计耗时 | 获取方式 |
|---|---|---|---|---|---|---|---|

### 一周路线（严格 20% 理论 / 80% 实践）

| 天 | 理论（分钟） | 实践（分钟） | 今日主题 | 交付物 | 卡住时的降级方案 |
|---|---|---|---|---|---|
| D1 | 24 | 96 | | | |
...
| D7 | 24 | 96 | | | |

### 学习时间分配校验
理论总计 X 分钟（Y%）/ 实践总计 Z 分钟（W%）
```

**硬性约束**：

- 资料优先：官方文档 > 标准/教材 > 经典书 > 高质量课程 > 博客/视频
- 每份资料必须指定精读范围，禁止"通读全书"
- 每天必须有一个**降级方案**（时间不够/环境跑不起来时做什么）
- 比例校验必须真的接近 20/80，否则重写

## Step 6：5 阶通关卡牌（微实践）

**目标**：把"学会"拆成 5 个可检测的等级，每级有一个能拿出来的微交付物。

**输出骨架**：

```markdown
| 等级 | 名称 | 能力描述（能做什么） | 达标标准（可客观检测） | 踩坑预警 | 微实践交付物 | 预计时间 | 升级判定 |
|---|---|---|---|---|---|---|---|
| L1 | 复刻 | | | | | | |
| L2 | 变形 | | | | | | |
| L3 | 排错 | | | | | | |
| L4 | 选型/决策 | | | | | | |
| L5 | 交付/教学 | | | | | | |

**升级判定通用规则**：交付物提交给 AI 审查 → 通过才升下一级；未通过给出具体缺口清单。
```

**硬性约束**：

- 5 级按"复刻 → 变形 → 排错 → 决策 → 交付/教学"递进，难度单调上升
- 达标标准必须是**能被第三方判定的**（跑通 N 个用例 / 指标达到 X / 输出包含 Y 项），不能写"感觉掌握了"
- 交付物是实体：文件、链接、截图、数据表、录屏、一段讲稿

## Step 7：20 小时攻坚 + S 级实战项目（SOP）

**目标**：给一个能写进作品集的完整项目，步骤细到小白照做即可。

**输出骨架**：

```markdown
### 20 小时拆解

| 模块 | 时长 | 目标 | 对应 L 几 | 产出 |
|---|---|---|---|---|

### S 级实战项目：<项目名>

**0. 准备工作**
- 环境/账号/素材：<清单>
- 前置检查项：<命令或点击，确认通过的标志>
- 预计总时长：

**Step 1 - <动作名>**
- 做什么：
- 具体指令：
- 成功标志（DoD）：
- 失败了怎么办：<回滚/排查>

**Step 2 ...**

**最终交付标准（Definition of Done）**
- [ ] 可运行的产物（链接/文件）
- [ ] 通过 N 项自检清单
- [ ] 一份 200 字复盘：最难的一步 + 为什么 + 下次怎么改

**AI 诊断入口**
> 把以下内容发给我，我做诊断：<提交物清单 + 你想让我重点看什么>
```

**硬性约束**：

- 每个 Step 必须同时覆盖三态：**成功标志 / 失败排查 / 卡住求助话术**
- 包含**防重触发与回滚**：重复执行会怎样、如何撤销
- 项目难度匹配用户当前水平（依据 Step 6 的 L 级定位）
- DoD 必须可勾选

## Step 8：10 道实战场景考核（毒舌考官模式）

**目标**：用真实场景逼出真本事，单题过关，答错讲透再出变式题。

**执行协议**：

1. 一次只出**一题**，等用户作答
2. 判分：给出 通过 / 不通过 + 毒舌点评（不超过 3 句，句句见血）
3. 不通过 → 点破错因（指出错的是哪个概念）→ 用 5 句话讲透 → 出**变式题**（同考点、不同场景）
4. 变式题仍不通过 → 降难度出**铺垫题**（更基础的同一考点），通过后再回到变式题
5. 题号只在通过后 +1；10 题全过才进 Step 9
6. 顶部显示：`当前进度：第 N/10 题 | 已答错 M 次`

**出题骨架**：

```markdown
### 第 N 题（考点：<考点>）

**场景**：<真实报错日志 / 突发状况 / 两难决策，3-6 行>
**你的任务**：<一句话：发生了什么？你怎么处理？为什么？>
**评分点**：
1. 能否定位到 <核心点>
2. 是否说出 <边界条件>
3. 方案是否可执行（给具体动作而非原则）
```

**硬性约束**：

- 场景必须是**真实世界的报错、事故、客户刁难、资源受限、需求突变**，不是概念默写
- 每题有唯一或明确的评分点，不能模棱两可
- 毒舌但不人身攻击：批的是答案，不是人
- 10 题覆盖 Step 6 的 5 个等级（每级 2 题）

## Step 9：费曼学习法（人机角色互换）

**目标**：让学习者用大白话讲出来，暴露"以为懂了其实没懂"的地方。

**执行协议**：

1. 给出讲解任务："请用 3-5 分钟，把我当成 12 岁小孩，讲清楚 <知识点>。禁止使用 <列出 3-5 个术语>。"
2. 用户讲完后，以 12 岁小孩口吻追问，**一次问 1-2 个问题**，不要一次甩 5 个
3. 追问库（按优先级使用）：
   - "为什么呀？"（追问因果）
   - "这个词啥意思？能不能换个说法？"（追问术语依赖）
   - "打个比方呢？比如用做饭/上学/打游戏来比？"（追问类比能力）
   - "那如果 <边界条件改变> 会怎么样？"（追问边界）
   - "你刚才说的 A 和 B 是一回事吗？"（追问概念混淆）
   - "少了它会怎样？为什么非得有它？"（追问必要性）
4. 连续 2 轮能答上来且无术语 → 判定通过；卡壳 → 用大白话补讲 5 句，再追问同一考点
5. 全部知识点（通常 3-5 个核心概念）讲透后进入 Step 10

**通过标准**：无术语堆砌 + 有生活化类比 + 能说出边界条件 + 能回答"为什么非得这样做"

---

## Step 10：战地速查表与 Skill 沉淀

**目标**：把踩过的坑、用过的公式固化成一张能贴墙的表。

**输出骨架**（写入 `<工作区>/<主题>-速查表.md` 并交付）：

```markdown
# <主题> 战地速查表

## 1. 核心概念（一句话白话版）
| 概念 | 白话解释 | 什么时候用 | 容易混淆 |
|---|---|---|---|

## 2. 报错 / 异常 → 原因 → 解法
| 现象 | 最可能原因 | 排查顺序 | 解法 | 如何避免再犯 |
|---|---|---|---|---|

## 3. 核心公式 / 参数 / 清单
<代码块或表格>

## 4. 决策树
<什么情况下选 A，什么情况下选 B>

## 5. 我踩过的坑（本次学习实测）
| 坑 | 当时现象 | 耗时 | 正确做法 |
|---|---|---|---|
```

**硬性约束**：

- 至少 8 条报错条目、5 个核心概念
- 每条必须给**排查顺序**（第一步看什么），不是只给解法
- 写成文件交付，不要只在对话里贴

## Step 11：艾宾浩斯 15 核心知识点记忆系统

**目标**：把 15 个核心知识点做成闪卡，配 1-3-7-15-30 天复习计划。

**闪卡结构（严格 15 张，缺一不可）**：

```markdown
### 卡片 N：<知识点名>
- **场景问题**：<一个真实场景里冒出来的问题>
- **白话答案**：<3 句话以内，12 岁能懂>
- **关键细节**：<数字 / 公式 / 边界条件>
- **记忆口诀**：<一句话，押韵或动作化>
- **易混点**：<和什么搞混，怎么区分>
- **复习节点**：D1 / D3 / D7 / D15 / D30
```

**复习计划表**：

```markdown
| 批次 | 复习日 | 卡片范围 | 方式 | 完成打勾 |
|---|---|---|---|---|
| R1 | Day 1 | 1-15 | 看场景问题 → 口述答案 → 翻卡核对 | [ ] |
| R2 | Day 3 | 1-15 | 只看口诀 → 还原答案 | [ ] |
| R3 | Day 7 | 错卡优先 + 全量 | 默写 | [ ] |
| R4 | Day 15 | 错卡 + 随机 5 张 | 口述 | [ ] |
| R5 | Day 30 | 全量 | 给他人讲一遍（费曼） | [ ] |
```

**硬性约束**：

- 严格 15 个知识点，覆盖：3 个底层原理 + 5 个高频操作/概念 + 4 个易错点 + 3 个决策规则
- 每张卡的"场景问题"必须是问题，不是标题
- 口诀必须短（≤20 字）且可复述
- 生成日历时给出**具体日期**（依据当前日期推算，不要写"Day 1"了事）
- 骨架文件：`assets/flashcard-deck-template.md`
